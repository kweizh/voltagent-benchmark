## What was implemented

```ts
import { createWorkflowChain, andThen } from "@voltagent/core";
import { z } from "zod";

const workflow = createWorkflowChain({
  id: "conditional-operation-workflow",
  name: "Conditional Operation Workflow",
  input: z.object({ value: z.number(), operation: z.string() }),
  result: z.object({ result: z.number() }),
})
  .andWhen({
    id: "double-step",
    condition: async ({ data }) =>
      (data as { operation?: string }).operation === "double",
    step: andThen({
      id: "do-double",
      execute: async ({ data }) => {
        const d = data as { value: number; operation: string };
        return { result: d.value * 2 };
      },
    }),
  })
  .andWhen({
    id: "square-step",
    condition: async ({ data }) =>
      (data as { operation?: string }).operation === "square",
    step: andThen({
      id: "do-square",
      execute: async ({ data }) => {
        const d = data as { value: number; operation: string };
        return { result: d.value * d.value };
      },
    }),
  });

export default workflow;
```

## Key design decisions

- **`andWhen` with `step`**: The `WorkflowStepConditionalWhenConfig` type requires a `step` (an `InternalAnyWorkflowStep`), so each conditional branch wraps its logic in `andThen(...)` which produces a `"func"` step.
- **Two `andWhen` steps in sequence**: The first handles `operation === 'double'` (returns `{ result: value * 2 }`), the second handles `operation === 'square'` (returns `{ result: value * value }`). Only the matching condition executes; the other passes data through unchanged.
- **Type casts**: Because `andWhen` returns a union type (`NEW_DATA | CURRENT_DATA`) after the first conditional step, TypeScript requires explicit casts on `data` in subsequent steps to access the original input fields.
